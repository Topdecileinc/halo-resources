Halo Email Resources

Getting Started (root)

  • Orchestrator (prompt_email_generation.md) The entry point the engine reads first: the build flow, the prefix system, and how every resource fits together. Load this as the chatbot's instructions.
  • Developer README (README.md) How the engine is built and the two ways to run it (chat or pipeline) — including exactly what to load into the chatbot.
  • Docs-site setup (INSTALL.md) How this GitHub Pages documentation site is wired: the layout, front matter, and the auto-built sidebar.

Brand Guidelines (brand-guidelines/)

  • Brand guidelines (rules_brand.md) The one brand-level file. Inside it: brand identity (name, site, voice, logo), audience segment definitions, email copy rules, and the product facts — membership, social proof (reviews), and technical features (specs). All relayed verbatim.

Email Design System (email-design-system/)

  • Email style guide (rules_email_style_guide.md) Visual standards: colors, typography, layout, button variants. Values come from the Figma design system.
  • Email build rules (rules_email_build.md) HTML / code standards: table layout, inline CSS, Outlook/MSO handling, image markup, class conventions, and the pre-delivery checklist.
  • Footer rules (rules_email_footer.md) The stable footer, legal line, unsubscribe text, and hosted social-icon URLs used on every email.
  • sections/ The reusable section blocks an email is built from — section_*.html: header, footer, tech specs, reviews, membership.
  • components/ Reusable primitives used inside sections — component_*.html (the bulletproof CTA button).
  • playground/ Interactive in-browser previews of each section and component (for humans, not loaded into the chatbot): edit the values, then copy the HTML.
  • assets/ Reference copies of the brand images and social icons (img_*.webp, social_*.webp). Emails link to the hosted URLs in the rule files, not these files.

Developer Skills (developer-skills/)

  • Braze send rules (rules_braze_send.md) /messages/send schema and safety constraints.

Email Examples (email-examples/)

  • Sample emails (sample_*.html) Five real, shipped emails. Loaded into the chatbot as tone + HTML-structure reference only — never a source of facts. View the source on GitHub.

Brief (brief/)

  • Brief template (brief_sample.md) The blank, annotated brief — one per campaign. Defines every field the engine reads: segment, occasion, offer, hero URL, CTAs, and which sections to include.
  • Open the brief form (form.php) The PHP pipeline's interactive form, running (hosted separately): fills the brief, generates the email, previews it, and test-sends via Braze.
  • Pipeline source (form.php, config.sample.php, lib/) The PHP behind the form: form.php, config.sample.php (copy to config.php for keys), and lib/claude_pipeline.php (calls Claude, validates, previews, sends via Braze).

Validation (test/)

  • Validation documentation What each validator module does, with check IDs and limits.
  • Test harness source (validate.py, config.ini, validators/) The zero-dependency Python validator: validate.py (entry point), config.ini (paths/toggles), and the validators/ modules. View on GitHub.
