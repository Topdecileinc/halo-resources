# Halo styled docs — how the docs site is set up

The markdown files in this repo render as a styled GitHub Pages site: every page gets the
Halo header, an auto-generated "On this page" sidebar, and a readable content column —
matching the index page. This file documents how that's wired and how to work with it.

> **Scope:** this is about the **docs site** (the GitHub Pages rendering of the markdown).
> It's separate from the email engine itself (the rules, the brief form, the pipeline).

## What makes it work

| File | What it does |
|---|---|
| `_layouts/default.html` | The page template every markdown file is wrapped in — header, sidebar, content styling, and the JavaScript that builds the on-page table of contents. |
| `_config.yml` | Tells Jekyll to apply the `default` layout to every page automatically, and excludes non-page files (the `test/` harness, the PHP form, `*.py`, etc.) from being published. |
| `add_frontmatter.py` | One-off helper that adds the empty `---\n---` front-matter block Jekyll needs to treat a `.md` file as a styled page. |

The folder `_layouts` has a leading underscore — that's Jekyll convention and is required for
it to be picked up. There is **no** `_includes/` folder and no separate nav file: the sidebar
is generated by the layout itself (see "The sidebar" below).

## Recreating it from scratch

If you ever need to stand the styling back up:

1. Put `_layouts/default.html` at the repo root (inside `_layouts/`).
2. Put `_config.yml` at the repo root.
3. From the repo root, run the front-matter helper once:
   ```bash
   python3 add_frontmatter.py
   ```
   It adds a tiny `---\n---` block to every markdown file so Jekyll renders it as a styled
   page (otherwise it serves raw markdown). The script is idempotent — re-running it skips
   files that already have the block. You can leave the script in the repo; `_config.yml`
   excludes `*.py` from publishing, so it never ships as a page.
4. Commit and push. GitHub Pages rebuilds in 60–90 seconds.

After the rebuild, any markdown file is reachable at its `.html` URL, for example:
- `https://topdecileinc.github.io/halo-resources/README.html`
- `https://topdecileinc.github.io/halo-resources/brand-guidelines/rules_brand.html`

GitHub Pages serves `.md` files at `.html` URLs (the `.md` extension lives in the repo, the
`.html` extension on the live site).

## Adding a new doc page

Just create a `.md` file anywhere in the repo. It automatically gets the layout, the header,
and the sidebar — no front matter required (the `_config.yml` default applies the layout).

To make a new page **discoverable**, link to it from the home page (`index.html`, the "All
resources" landing page) — that's where cross-page navigation lives. There is no nav list to
maintain.

To set a custom page title or an eyebrow label above the H1:

```
---
title: Brand identity
eyebrow: Brand standards
---

# My Page

Content here.
```

`title` overrides the site default in the browser tab; `eyebrow` renders as small uppercase
text above the H1.

## The sidebar (it's a table of contents, not a nav)

The left sidebar is **not** a list of all pages. The layout's JavaScript walks the current
page's `H2`/`H3` headings, gives each an anchor ID, and builds an "On this page" table of
contents from them — with the active section highlighted as you scroll. Above it sits a
"← All resources" link back to the home page. So there's nothing to edit per page: write good
headings and the TOC follows automatically.

## What it looks like

- **Header:** sticky, frosted-glass, Halo logo on the left, "Email Resources" tag on the right.
- **Sidebar:** 260px wide, sticky as you scroll — the auto-built on-page TOC plus the back link.
- **Content:** a readable column, Inter font, generous whitespace.
- **Tables, code blocks, blockquotes:** styled to match the Halo look.
- **Mobile:** the layout collapses to a single column and content fills the width.

## Troubleshooting

**Pages still showing an old / unstyled theme?**
Hard-refresh your browser (`Cmd+Shift+R` / `Ctrl+Shift+R`). GitHub Pages serves cached
versions for a few minutes after a deploy.

**A new page isn't linked anywhere?**
Add a link to it from `index.html`. The site has no auto-generated page list — the home page
is the index.

**Build failed?**
Check the Actions tab on GitHub. The usual cause is a YAML syntax error in `_config.yml` —
make sure indentation uses spaces (not tabs) and quote strings that need it.
